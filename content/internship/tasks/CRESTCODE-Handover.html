1. 專案情境與範圍

CRESTCODE 是提供 HCP 使用的 LINE LIFF 家族案例挑戰。V2-1 將舊版兩題式體驗改成選擇家族角色、回答一題、查看解析與影片，再完成角色挑戰。V2-2 在既有流程加入 11 張卡牌抽取與收藏；前端是 Angular LIFF，後端使用 Bun／Elysia API、Firebase Authentication 與 Firestore。

我負責需求收斂、OpenSpec 規格、前端卡牌結果／收藏初版、測試站 API 串接、前端 build 與元件測試。後端實作及我離開後的 review 修正、整合驗收與部署由其他工程師接手。

3. 身分情境與基本流程

LIFF 初始化後由後端依 Firebase ID token 判定身份；前端不可用 URL 中的 LINE UID 作為身份依據。

身分進入方式
已驗證 HCP直接進家族樹。
待驗證 HCP依既有資料進家族樹；已有 profile 不要求重填。
未驗證 HCP沒有既存 profile 時先填姓名、縣市與服務院所，再進家族樹。
已註銷 HCP顯示阻擋頁，不允許開始遊戲。

V2-1 基本流程

LIFF 初始化 → 身分判定 →（必要時填基本資料）→ 家族樹選角
→ 題目 → 後端判分 → 解析／Reference → 影片 → 教材／結果 → 角色完成並解鎖
  • 同角色未完成流程恢復原進度；切換角色時載入該角色自己的狀態。
  • 作答由後端判分；只有後端到達 completed 才解鎖角色。
  • 影片以原生 video controls／playsinline 播放，並保留外部開啟方式。

V2-1 前端主要回饋

  • 題目與案例圖片載入前顯示載入狀態，避免空白；角色選取狀態與已完成／解鎖狀態分開呈現。
  • 手機影片採 GCS MP4、原生 controls／playsinline，並保留外部開啟方式；結果頁提供教材與下一步入口。
  • 院所選擇需支援搜尋並提供手動處理方式；profile 欄位與題目標題／字級依前端回饋調整。

V2-2 抽卡流程

家族樹選角色 → 題目 → 解析 → 影片頁 → 點 Galaxy News
→ 後端保存抽卡結果 → 彈窗由下往上進場
→ 彈窗到位後背景切換 → 正面 3 秒 → 翻至背面停留
  • Galaxy News 抽卡按鈕在影片頁，不在結果頁；不要求影片播完。
  • 收藏入口只在家族樹與挑戰完成頁，固定懸浮右下角，不額外加字。
  • 每次呈現抽卡結果（新抽、同日重複、恢復已存結果）都正面 3 秒後翻背；重試不得換卡。
  • 收藏詳情點下方文字手動翻面；卡牌放大／觸控縮放後來決定暫緩。

每日抽卡與日期

  • 卡池固定 11 張；V2-1 舊遊玩不補收藏。
  • 有效日期依角色遊玩 `startedAt` 的 Asia/Taipei 日期，抽卡時間另行記錄；23:59 開始、00:01 點擊仍屬前一天。
  • 新有效日期首抽從未收藏卡等機率抽取；同日其他局固定同卡。
  • 集滿 11 張後，新有效日期從全部 11 張等機率抽一張，收藏仍為 11/11。

5. 資料模型與 API 契約

Firestore

sites                                      ← collection
└─ {site}                                  ← site 文件，例如 astrazeneca
   └─ hcpChallengeV2                       ← challenge 子集合
      └─ {challengeId}                     ← 玩家／challenge 文件
         └─ cardDraws                       ← 此 challenge 文件底下的子集合
            └─ {cardDrawId}                 ← 一局遊戲的卡牌紀錄文件
  • 完整路徑範例：sites/astrazeneca/hcpChallengeV2/abc123/cardDraws/run456。sites、hcpChallengeV2、cardDraws 是集合；astrazeneca、abc123、run456 是文件。
  • cardDraws 是 sites/{site}/hcpChallengeV2/{challengeId} 文件底下的子集合；它不是該文件中的欄位或陣列，也不是最上層獨立集合。
  • challengeId 沿用既有玩家／challenge 文件，不是每局重建；每次角色遊玩都在其 cardDraws 子集合新增一份 cardDrawId 文件。
  • 每份 cardDraws/{cardDrawId} 保存一局的開始時間、角色、進度、完成狀態、事件及抽卡結果。
  • parent 的角色摘要保留目前／可恢復的 cardDrawId。
  • 不新增獨立玩家收藏、collection summary 或每日卡牌文件；收藏由有效 cardDraw records 推導。
  • V2-1 舊 parent 沒有 cardDraws 時沿用舊流程與報表，不搬移、不補卡。

V2-2 卡牌 API 增量

共用前綴 /az-hcp/hcp-challenge/v2；身份來自 Bearer token。

端點契約重點
POST /az-hcp/hcp-challenge/v2/draw-cardRequest 必須含 site、challengeId、cardDrawId；回應含 effectiveDate、drawnAt、reusedExistingResult 等。
POST /az-hcp/hcp-challenge/v2/card-collection回傳 11 張卡；摘要為 summary.collectedCount、summary.totalCount、summary.isComplete。
POST /az-hcp/hcp-challenge/v2/start新 V2-2 flow 傳 cardDrawId: null opt in；保存回傳的 cardDrawId／cardDraw 供恢復。

報表

每個 V2-2 cardDraw record 一列，新增欄名「當次遊戲抽的卡牌」。有效結果填英文卡名，缺少／無效填 N；遊戲完成欄沿用原判定。舊 V2-1 記錄維持既有 flatten，卡牌欄填 N。

7. 本機測試與 Stage 注意事項

# 前端 repository
npm start

# 另一個 terminal，需要 LIFF 時
npm run serve:liff

# Stage configuration build
npm run build-stage
  • LIFF 初始化失敗時檢查 site query、channel／redirect URL 與 Angular server 是否在 4200 運作。
  • 當時 Stage workflow 以 s* tag 觸發 build-stage 並部署 Stage hosting；操作前先核對目前 workflow 與 target。
  • Stage smoke test需涵蓋身份、恢復、影片頁抽卡、同日重抽、滿卡抽取、收藏與報表欄位。
  • 禁止把 token、API key、醫師個資或 production secrets 放入文件或 Git。
